# Review Format

Use the full report by default for completed articles. Use the compact report when the user requests a quick check or when the draft is short and has few findings.

## Severity

- **P0 — Publication blocker:** A credible risk of material falsehood, harmful advice, serious misattribution, privacy exposure, legal/copyright trouble, or a failure that defeats the article's purpose.
- **P1 — Major:** A substantial problem in accuracy, logic, structure, missing context, or reader comprehension that should be fixed before publication.
- **P2 — Moderate:** A localized issue that weakens clarity, pace, credibility, analytical depth, or natural keyword use.
- **P3 — Polish:** A low-risk improvement to wording, rhythm, consistency, or presentation.

Severity expresses impact, not certainty. State uncertainty separately.

## Finding status

Use one of these labels for fact-related findings:

- **Contradicted:** Reliable evidence conflicts with the statement.
- **Unsupported:** The supplied material does not support the statement.
- **Time-sensitive:** The statement may have changed and needs a current source.
- **Needs verification:** The claim is plausible but cannot be responsibly confirmed from available evidence.
- **Verified:** Use sparingly, only when verification was actually performed.

## Dimension ratings

Rate each applicable dimension as:

- **Good:** No material issue found.
- **Needs improvement:** One or more meaningful fixes are advisable.
- **Serious concern:** Publication should wait for correction or verification.
- **Not assessable:** Essential context or evidence is unavailable.

Do not convert these ratings into a numerical score unless the user requests one.

## Full report

### Editorial verdict

Give one verdict and a one- or two-sentence reason:

- **Ready to publish**
- **Ready after minor edits**
- **Hold for revision**
- **Hold for verification**

State the article's inferred promise and intended reader if that context affected the review.

### Priority findings

Order findings by severity and reader impact.

| Priority | Location | Issue | Why it matters | Recommended action |
|---|---|---|---|---|
| P1 | H2 “…” / opening sentence | Concise diagnosis | Specific impact | Concrete edit or check |

For factual findings, include the status, the source or missing evidence, and the precise human check needed. Quote only enough text to locate the problem.

### Delete or compress

List sentences, paragraphs, or sections that can be removed or merged. Explain what is duplicated or what information would be lost. Say `None` when there is no defensible deletion candidate.

### Human verification required

Use a checklist ordered by risk. Include names, dates, numbers, quotations, attributions, technical assertions, permissions, links, and time-sensitive claims only when they actually require checking. State how to verify each item.

### Strongest elements

Identify up to three elements worth preserving. This prevents later revisions from erasing the article's voice or strongest reasoning.

### Recommended revision order

Give a short dependency-aware order: blockers and evidence first, then structure and missing explanation, then line editing and polish.

## Compact report

Return:

1. Verdict.
2. Up to five findings in priority order.
3. Human checks, if any.
4. One strongest element to preserve.

## Clean review behavior

If no material issue is found, say so directly. Do not invent minor objections for completeness. Mention any limits caused by missing sources, brief, audience information, or access to linked content.
